# 哈希表

哈希表（Hash Table / HashMap）通过哈希函数将 key 映射到存储位置，实现近似 O(1) 的查找。

---

## 工作原理

```
键(key)  →  哈希函数  →  存储位置(槽)
"name"   →  0x3A8F2D  →  数组[0x3A8F2D % size]
```

### 理想情况

每个 key 都映射到不同的槽位——O(1) 查找。

### 哈希冲突

不同 key 映射到同一个槽位——必然会发生（鸽笼原理）。

---

## 解决哈希冲突

### 链地址法

每个槽位存储一个链表（或红黑树）。冲突时往链表末尾添加。

```
槽位:  [0]  →  ("age") → ("weight")
       [1]  →  ("name")
       [2]  →  ("height") → ("score")
```

**采用者**：Java `HashMap`（链表长度 > 8 转为红黑树）

### 开放寻址法

冲突时按某种策略找下一个空位：

```
插入 "age" → 槽 3 已占用 → 检查槽 4 → 空，放入
插入 "weight" → 槽 3 已占用 → 检查槽 4 被占用 → 检查槽 5 → 空，放入
```

**采用者**：`ThreadLocal`、Redis 字典

---

## 负载因子与扩容

| 项目 | 说明 |
|------|------|
| 负载因子 | `元素数量 / 槽位总数` |
| 默认负载因子 | 0.75（Java HashMap） |
| 扩容时机 | 负载因子超过阈值时 |
| 扩容操作 | 新数组大小 ×2，所有元素重新 hash |

> 负载因子越大越省内存但冲突越多，0.75 是时间与空间的平衡点。

---

## 适用场景

| 场景 | 说明 |
|------|------|
| 缓存 | 快速存储和读取（如 LRU Cache） |
| 字典 | 语言的语言包、配置项 |
| 去重 | 判断元素是否已经存在 |
| 计数 | 统计每个元素出现的次数 |
| 索引 | 数据库的哈希索引 |

> 哈希表的使用诀窍：**绝大多数"查找"问题，先想到哈希表**。它的 O(1) 查找很难被其他结构替代。
