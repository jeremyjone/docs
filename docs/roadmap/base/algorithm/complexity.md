# 复杂度分析

算法好坏用**时间复杂度**和**空间复杂度**衡量，用大 O 表示法描述执行时间随数据量增长的趋势。

---

## 常见复杂度

<img :src="$withBase('/assets/roadmap/base/time-complexity.svg')" alt="时间复杂度对比" style="max-width:100%;margin:20px 0;">

| 大 O | 名称 | 含义 | 示例 |
|------|------|------|------|
| O(1) | 常数时间 | 与数据量无关，一步到位 | 数组随机访问 |
| O(log n) | 对数时间 | 每步排除一半数据 | 二分查找 |
| O(n) | 线性时间 | 遍历所有数据一次 | 遍历数组 |
| O(n log n) | 线性对数 | 典型高效排序 | 归并排序、快速排序 |
| O(n²) | 平方时间 | 两层嵌套循环 | 冒泡排序 |
| O(2ⁿ) | 指数时间 | n 一大就爆炸 | 朴素斐波那契递归 |

---

## 如何估算

1. **忽略常数项** — O(2n) 写作 O(n)，O(n/2) 也写作 O(n)
2. **取最高次项** — O(n² + n) 写作 O(n²)，O(n + log n) 写作 O(n)
3. **关注最坏情况** — 通常分析最坏时间复杂度

```text
// O(1)
arr[i] = 42;

// O(n)
for (let i = 0; i < n; i++) { arr[i] *= 2; }

// O(n²)
for (let i = 0; i < n; i++) {
  for (let j = 0; j < n; j++) {
    sum += matrix[i][j];
  }
}
```

---

## 空间复杂度

同样用大 O 表示，衡量算法占用的额外内存空间：

| 空间 | 含义 | 示例 |
|------|------|------|
| O(1) | 只用了几个变量 | 冒泡排序 |
| O(n) | 需要一个额外数组 | 归并排序 |
| O(log n) | 递归栈深度 | 快速排序 |
| O(n²) | 二维矩阵 | 邻接矩阵图算法 |

---

## 实操参考

| 数据量 | 可接受的复杂度 |
|--------|---------------|
| n < 100 | O(n²) 也能跑 |
| n < 10³ | O(n²) 勉强 |
| n < 10⁵ | 必须 O(n log n) 或更低 |
| n < 10⁷ | 只能 O(n) 或更低 |
| n < 10⁹ | 只能 O(log n) 或 O(1) |

> 估算的优先级：先考虑 n 有多大，再选合理的算法。大多数业务场景 n < 10⁶，O(n log n) 是最佳区间。
