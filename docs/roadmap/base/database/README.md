# 数据库

数据库（Database）是按特定结构组织、存储和管理数据的系统。在计算机体系中，数据库是应用程序持久化数据的核心组件。

> 本节从基础概念入手，不绑定具体数据库产品（MySQL、PostgreSQL 等），先建立通用认知。

## 关系型数据库

关系型数据库以"表"为核心，数据以行（记录）和列（字段）的形式存储，表之间通过外键建立关联。

**核心概念**：

| 术语 | 含义 |
|------|------|
| 表（Table） | 实体集合，如 `users` 表 |
| 行（Row） | 一条记录，如一个用户 |
| 列（Column） | 一个属性，如 `name`、`age` |
| 主键（Primary Key） | 唯一标识一行记录的字段 |
| 外键（Foreign Key） | 关联其他表的字段 |
| 索引（Index） | 加速查询的数据结构 |
| SQL | 操作数据库的标准化语言 |

## SQL 四大操作

**DDL（数据定义）**：`CREATE`、`ALTER`、`DROP`——定义表结构
**DML（数据操作）**：`INSERT`、`UPDATE`、`DELETE`——操作数据
**DQL（数据查询）**：`SELECT`——最常用的查询语句
**DCL（数据控制）**：`GRANT`、`REVOKE`——权限管理

### 一个简单的查询示例

```sql
SELECT u.name, o.amount
FROM users u
JOIN orders o ON u.id = o.user_id
WHERE o.status = 'paid'
ORDER BY o.created_at DESC
LIMIT 10;
```

这条语句做了：联表查询 → 条件过滤 → 排序 → 分页，覆盖了日常 80% 的查询模式。

## 事务与 ACID

事务（Transaction）是一组不可分割的数据库操作，要么全部成功，要么全部回滚。

**ACID 四大特性**：

| 特性 | 含义 | 类比 |
|------|------|------|
| A（原子性） | 事务不可分割 | 转账：扣钱和加钱同时成功或同时失败 |
| C（一致性） | 数据永远符合规则 | 余额不能为负数 |
| I（隔离性） | 事务之间互不干扰 | A 转账时 B 看到的是转前或转后的结果 |
| D（持久性） | 提交后数据不丢失 | 写入磁盘，不等缓存 |

### 隔离级别

| 级别 | 脏读 | 不可重复读 | 幻读 |
|------|------|-----------|------|
| 读未提交 | ✓ 可能 | ✓ 可能 | ✓ 可能 |
| 读已提交 | ✗ | ✓ 可能 | ✓ 可能 |
| 可重复读 | ✗ | ✗ | ✓ 可能（InnoDB 通过 MVCC 解决了） |
| 串行化 | ✗ | ✗ | ✗ |

> **默认级别**：MySQL InnoDB 是**可重复读**，PostgreSQL 是**读已提交**。

## 索引

索引是加速数据查询的数据结构，相当于书的目录。最常用的是 **B+ 树索引**。

**索引类型**：
- **主键索引**：聚簇索引，数据按主键顺序物理存储
- **二级索引**：非聚簇索引，存主键值，需要回表查询
- **联合索引**：多列组合，遵循最左前缀原则
- **唯一索引**：确保字段值唯一

> **索引不是越多越好**：每次插入/更新都要维护索引，写性能会下降。

## 非关系型数据库（NoSQL）

关系型数据库不是万能的，特定场景下 NoSQL 更合适：

| 类型 | 代表 | 适用场景 |
|------|------|---------|
| 键值存储 | Redis | 缓存、会话、计数器 |
| 文档型 | MongoDB | 灵活 Schema、JSON 数据 |
| 列族型 | Cassandra | 海量时序数据 |
| 图数据库 | Neo4j | 社交关系、推荐系统 |

## 常见问题

**N+1 查询**：循环中逐条查询关联数据，应改用 JOIN 或批量查询。

**慢查询**：通过 `EXPLAIN` 查看执行计划，检查是否走索引。

**连接池**：建立数据库连接开销很大，应用层需要用连接池复用连接。
